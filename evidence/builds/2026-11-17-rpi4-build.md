# Raspberry Pi 4 image build and offline verification

Date: 17 November 2026. Machine: raspberrypi4-64. Planned board: borrowed Pi 4,
8 GB. This report records build/offline inspection only, not a physical boot.

`bitbake core-image-morse-dev core-image-morse` completed all 4,864 tasks.
Both production and development SD images were generated. Kernel recipe:
6.6.63; driver: 0.4; daemon/HUD: 1.0. Pinned sources are in manifest/source-pins.md.

## Development image verification

- Fully decompressed the bz2 stream, validating its integrity.
- Checked the MBR signature and FAT boot/Linux root partitions.
- Verified kernel8.img, config.txt, Pi 4 DTB and start4.elf on the actual FAT partition.
- Checked the ARM64 kernel Image header, UART configuration and root partition
  command line. HDMI tty1 login is present in inittab.
- Checked the installed, XZ-compressed module: AArch64 ELF; vermagic
  6.6.63-v8 SMP preempt mod_unload modversions aarch64.
- Checked receiver vendor/product selection (3151/1020), Wi-Fi interface
  configuration, hostname, and key-only SSH configuration in the actual image.
- Compared installed Wi-Fi profile/public key with the private local source
  without displaying their values. Root-owned Wi-Fi/key files use mode 0600;
  the SSH directory is root-owned mode 0700.
- The public/default QEMU production build also passed (4,134 tasks), with
  private access disabled. Its manifest/rootfs contain no provisioned access
  package, Dropbear server, authorized key or local Wi-Fi profile.
- GCC -fanalyzer and strict warning checks passed for the new userspace C tools.

The Pi 4 firmware defaults to 64-bit kernel8.img; an explicit arm_64bit=1 line
is not required. The verifier rejects an explicit 32-bit override and checks
the actual kernel header. See the
[official boot documentation](https://github.com/raspberrypi/documentation/blob/master/documentation/asciidoc/computers/config_txt/boot.adoc).

## Resolved build/setup issues

- Replaced the slow full kernel-history fetch with a depth-one cache at the
  exact pinned commit. No source revision or integrity check was weakened.
- Corrected the optional access recipe's MIT checksum typo using the actual
  common license file; licensing QA remained enabled.
- Assigned the Pi modprobe configuration to FILES/CONFFILES after packaging
  QA reported it installed but unshipped. Packaging then passed.
- Image verification handles the BSP's standard .ko.xz module compression.
  Initial verifier assumptions were corrected against the actual image/BSP
  and official boot documentation; they were not counted as image failures.

## Remaining acceptance

No card has been written and no physical board boot has been tested. The owner
deferred card insertion/writing. Physical Wi-Fi association, USB/HID descriptors,
real button events, grab/release, unplug/replug and end-to-end text entry remain
for the borrowed-board session. Issues #2 and #11 stay open. The final video and
submission remain in #12. Power execution remains deferred until after submission.

The provisioned image contains a private network profile and is retained locally;
do not publish it as a GitHub release. The JSON report includes artifact hashes
and offline verification results, with no network credential values.

The final VM test-runner check used snapshot mode: key login passed, password authentication was rejected, and the base ext4 image checksum was unchanged. Source-level Python/shell checks and static analysis completed without diagnostics. Public wiki pages were verified without authentication (HTTP 200 and expected wiki titles).
